# README demos

The animations in the README are the real interface, filmed with [Flute](https://github.com/webprodigies-org/flute) (`@webprodigies/flute`, a frontend dev dependency, ADR-038). Flute places live React components on surfaces in a 3D scene, moves a camera across them and exports the result as an MP4. `scripts/make-demos.mts` then turns each MP4 into an animated WebP in `docs/media/`.

## Make the animations again

Do this when a change alters a page that an animation shows.

1. Start the app in development: `npm run dev`. The scenes load from the Vite dev server, and the Transcribe scene asks the backend for the real Whisper models.
2. Run `npm run demos` from the repository root. Pass scene ids to make only some, such as `npm run demos -- youtube-playlist themes`.
3. Look at every animation before you commit it.

You need FFmpeg built with libwebp on your `PATH` and Playwright's Chromium (`npx playwright install chromium` in `frontend/`). The MP4s stay in `frontend/.flute/exports/`, which git ignores.

## How the pieces fit

| Path | What it is |
|---|---|
| `frontend/src/flute/scenes/<id>.scene.json` | The recipe: camera, focus, the surfaces and the motion tracks. The `id` matches the file name. |
| `frontend/src/flute/scenes/<id>.tsx` | The component that puts real app components on the surfaces. Its `Surface` ids and `transform` props match the recipe's `nodes`. |
| `frontend/src/flute/demo/` | Helpers outside the scene folder: `DemoShell` (the real sidebar and top bar at a fixed 1440 by 900 window), `DemoDownloadPage` (the download page after a finished lookup), `TimedChecks` (ticks real checkboxes as the scene plays) and the fixtures |
| `frontend/src/flute/demo/fixtures/` | Real YouTube metadata for NASA's public videos, read through the app's own `GET /api/v1/youtube/media` on 2026-10-17, one file per video, playlist or channel tab, and the batch page's state built from them |
| `frontend/src/flute/ProjectPreview.jsx`, `catalog.js` | Generated by `npx flute init` and `npx flute sync`. Don't edit them. `ProjectPreview.d.ts` types the adapter for TypeScript. |
| `frontend/.flute/`, `frontend/FLUTE.md` | Flute's own project record and its note for coding agents |

`frontend/src/main.tsx` loads the Flute adapter only in development and only when the page URL has `?flute-preview=1`. A production build leaves Flute out completely. Open `http://localhost:5173/?flute-preview=1` to see the scene library, and add `&flute-scene=<id>` to open one scene.

## Add or change a scene

1. Read `frontend/FLUTE.md` and run `npx flute guide --json` in `frontend/`. The guide explains the camera, focus and motion model.
2. Add `<id>.scene.json` and `<id>.tsx` to `frontend/src/flute/scenes/`, then run `npx flute sync` in `frontend/`, because this project uses Flute's portable adapter.
3. Show real components with fixture data. Never redraw a page for a scene.
4. Check that `npx flute scenes --json` lists the scene with no issues, and that `npm run typecheck` and `npm run lint` pass.

Things learned while making the first six scenes:

- A surface's resting position comes from the `transform` prop on `<Surface>`. The recipe's `nodes` must match it, and the motion tracks animate from there.
- Several surfaces in one scene sit in normal page flow unless they are positioned. `themes.tsx` places both pages absolutely on the same origin.
- The page renders in the light theme in Flute's capture browser. A dark scene wraps its page in the `dark` class (`DemoShell isDark`).
- Lazy images never load on a page tilted in 3D, so `DemoShell` switches them to eager loading.
- Recipes use authored time at Flute's default half speed: 3500 authored milliseconds play for 7 seconds.

## Animation settings

`scripts/make-demos.mts` plays each scene at 0.7 times its length, at 12 frames a second, 800 pixels wide, as a lossy animated WebP at quality 75 that loops forever. A moving camera changes every pixel of every frame, which GIF compresses badly: the first GIFs were near 5 MB each, about 23 MB for the README, and loaded slowly on GitHub (issue #13). The WebP files keep full colour and are about a fifth of that size. GitHub serves `.webp` from a repository as `image/webp`, and every current browser plays it (ADR-039).
